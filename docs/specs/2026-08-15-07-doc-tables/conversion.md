# Conversion

Pipe tables become `json-table` blocks everywhere they can enter a document: a migration converts files as they are ingested (import and existing docs on upgrade alike), and the editor converts typed and pasted tables the moment they appear. Both paths are thin shells around one shared transform, so headers, keys, types, and captions come out identical no matter which door a table walked in through.

## Contract

### The shared transform

One pure function — `pipeTableToBlock` in `app/domain/data-blocks/table/from-pipe-table.ts`, this component's file inside the table block's directory — turns a parsed table shape into a `json-table` block. Its input is what every path can produce:

- header cells — a list of strings
- body rows — a list of string lists

Its output is the block per [table-block.md](table-block.md):

- `id` — freshly generated by the shared prefixed short-id generator (`app/lib/data-blocks/uuid.ts`), using the prefix `json-table` registers. The emitted JSON goes through `formatBlockJson`, which escapes backticks: a cell holding a fence would otherwise close the fence its own block is written into, truncating the block for every reader. Conversion always emits an id; a converted block never round-trips id-less through the registry's fill-missing-ids backstop, because the projection needs a stable id from the first sync.
- `caption.label` — empty string. A gfm table carries no caption, and deriving one from surrounding prose is guesswork; empty is honest, and the grid renders no caption line for an empty label ([grid.md](grid.md)'s chart convention) until someone names the table.
- `columns` — one per header cell, in order. `name` is the header text; an empty header cell gets the placeholder name `column_<n>` (1-based position). `key` is generated from `name` by [table-block.md](table-block.md)'s key rule, which also dedupes duplicate headers and reserves `file`. `type` comes from [cell-types.md](cell-types.md)'s inference over the column's body cells (number/date when more than half of non-empty cells parse, higher rate wins, ties to number, else text); a header-only table has nothing to infer from and gets all-text columns.
- `rows` — one object per body row, keyed by column key. Ragged rows are squared off the way gfm renders them: a row longer than the header is truncated, a shorter one padded with empty strings. Empty cells are stored as `""`.

Cell values are the cell's inner text as markdown source. The migration takes it from the mdast source span of the cell's children — not the span of the cell node, which includes its leading pipe and its padding. The live funnel has no source to slice, so it serializes the cell's inline content back to markdown through milkdown's own serializer, which is what keeps the two doors agreeing: reading a pasted cell's `textContent` instead would silently drop every mark and every link target. One residual difference is recorded rather than chased: remark escapes markdown punctuation on the way out, so a cell holding `2 * 3` migrates as written and pastes as `2 \* 3`. Characters are added, never lost, and both forms re-parse to the same inline content. Escaped pipes (`\|`) unescape to a literal `|`, and inline markdown (`**bold**`, links) is kept as its literal source characters — the grid renders strings, so formatting is lost visually but no characters are lost. The gfm alignment row is dropped; alignment has no field in the block, a deliberate loss. Cells that fail the inferred type stay exactly as written — red in the grid, NULL in SQL, per [cell-types.md](cell-types.md); conversion never edits a value to make it parse.

The transform is deterministic except for the generated id.

### Migration boundary

The migration `convert-pipe-tables` is raw markdown in, raw markdown out. Every table gfm parses is replaced by a `json-table` fenced block built by the shared transform; all other content is byte-preserved. A table inside a list item is replaced in place, with the item's line prefix carried onto every line of the fence, or the fence breaks out of the item that held it; those prefixes are spaces, which JSON ignores.

**A table inside a blockquote is lifted out of it**, and the quote resumes underneath:

````markdown
> Quoted intro

```json-table
{ … }
```

> Quoted tail
````

A fenced block cannot stay inside a quote: it would need `> ` on every line, and `parseCodeBlocks` does not strip that prefix — it is pinned by `parse.test.ts` and named in [spec.md](spec.md)'s must-not-change list, so it cannot be taught to. Prefixing emits JSON no reader can parse; in the editor it is worse than unreadable, because `validateStructural` rejects the fence and the file store refuses the whole write, so the user's paste is never saved. Lifting costs one blockquote becoming two. The quoted prose stays quoted, and the table's data reaches the grid and SQL. The replaced range widens to whole lines so the `> ` markers on the table's own lines go with it; a table inside a list inside a quote loses both the marker and the now-meaningless indent.

Both doors do this, and a test compares their output for the same source rather than trusting them to agree. What gfm does not parse as a table is not touched: pipe-shaped prose, a pipe block with no delimiter row, and any table sitting inside a fenced code block (where it is fence content, not a table) all pass through unchanged.

It runs wherever migrations run: registered in `app/domain/data-blocks/migrations/index.ts` and executed by `migrateFile` inside `ingestFile`, which per [spec 06](../2026-08-14-06-one-engine-load-and-import/spec.md) is the single entry for both boot-synced and dropped files. That one registration is what converts imports and upgrades existing projects; there is no second conversion site.

The migration itself has no side effects — persisting a rewritten synced file back to the server is ingest's existing behavior, not this migration's. It is idempotent structurally: a `json-table` fence contains no gfm table, so after one pass the migration's predicate finds nothing and the second pass is a no-op. One note for the machinery: the existing `Migration` shape gates on a json block type plus an old-shape zod schema, but this migration's trigger is a raw-markdown condition (a gfm table exists outside fenced code), so the `Migration` type grows a second, predicate-gated form — behavior of `migrateFile` and every existing migration is unchanged.

### Live boundary

Editor event in, block node replacing the table, two triggers:

- **Enter on a row-shaped line.** When Enter is pressed in a paragraph whose entire text is one pipe-delimited row — starts with `|`, ends with `|`, at least one cell — the paragraph is replaced by a `json-table` block whose columns are those cells (all text; nothing to infer from), with one empty body row and focus in the first cell. Focus is [grid.md](grid.md)'s affordance: both live triggers mark the new block id in `app/lib/editor/table-blocks/conversion-meta.ts`, and the grid's node view claims it once on mount. The channel is that module's pending-id set rather than a meta on the replacing transaction, because a node view mounts after the transaction that created its node and can never read it. The whole-paragraph requirement is the false-trigger guard: `either | or` mid-sentence never matches because the paragraph does not start and end with pipes, and the trigger never fires inside a code block node. A row-shaped line the user types but never commits with Enter simply stays prose — live conversion is an affordance, not a document invariant.
- **Any table node entering the document.** A plugin watches transactions (appendTransaction) and replaces every gfm table node in the incoming state with a `json-table` block via the shared transform — header row to columns, body rows to rows, type inference included. This one funnel catches every producer of table nodes: the clipboard plugin's parse of pasted markdown, pasted HTML tables (spreadsheets paste as HTML, which prosemirror parses into the same table nodes), and the gfm preset's own table input rules and insert commands. Those rules and commands are left in place but can no longer produce a _persistent_ table node: a table node may exist transiently inside a transaction, but never survives into committed editor state, so the serializer never again emits a pipe table. That is what "conversion is total" means here.

Side effects of the live path are the normal document-change flow: the replaced node serializes as the fenced block per [table-block.md](table-block.md), `onChange` carries it to the store, and sync projects it per [projection.md](projection.md). The grid the user sees is [grid.md](grid.md)'s renderer; conversion only makes the node.

## Prior art

- **Migrations machinery** — `app/lib/data-blocks/migrate.ts` defines `Migration` (`blockType` + old-shape zod + `upgrade`); `app/domain/data-blocks/migrations/index.ts` registers the list; `extract-annotations.ts` is the model migration. The new file is `app/domain/data-blocks/migrations/convert-pipe-tables.ts`, gated by the new raw-predicate form described above.
- **Scenario fixtures** — `app/domain/data-blocks/migrations/scenarios/` holds one directory per case with `input.md` and, iff the migration changes it, `expected.md`; `scenarios.test.ts` runs the full migration list over each and additionally re-migrates every `expected.md` asserting no change (idempotence). This migration's scenario dirs are named in Tests below.
- **Ingest seam** — `app/lib/files/ingest.ts` already runs `migrateFile` on every entering file and rejects a file whose migration throws; spec `2026-08-14-06` routes both boot sync and drop/import through it, so this migration needs no path-specific wiring.
- **Milkdown gfm and clipboard** — `app/ui/components/editor/MilkdownEditor.tsx` wires the `gfm` preset (parses pipe tables into prosemirror table nodes) and the `clipboard` plugin (parses pasted markdown and HTML into nodes). The callout-blocks plugin (`app/lib/editor/callout-blocks/`) is the nearest example of a block-level editor plugin with a node view; the live converter is a sibling plugin in that list.
- **Id generation** — `app/lib/data-blocks/uuid.ts`: `generateShortId` and the `<prefix>-<shortId>` shape, plus the registry id-path backstop (`fillMissingIds`) that this spec deliberately does not lean on for converted blocks.

Rejected close candidates:

- **Convert in the editor only** — rejected: SQL must see tables in documents the user never opens; only the migration reaches those.
- **Strip table nodes from the gfm schema** — rejected: the preset's remark-gfm parse and the clipboard plugin both assume the schema; converting table nodes after the fact keeps the preset intact and still guarantees none persist.
- **Convert at serialize time (markdownUpdated hook)** — rejected: the grid must appear the moment the user pastes, and rewriting during serialization fights the editor's canonical-echo cursor-stability check.

## Tests

### Skeleton

This component's slice of the walking skeleton: pasting a two-column pipe table (header plus one body row, one numeric column) into a document in the running app produces a `json-table` block — the table-node funnel fires, the shared transform infers one number column, and the block lands in the store for the rest of the skeleton (grid, projection) to pick up.

### Contract

Riskiest first:

- **Given** a table whose body row has more cells than the header, **when** converted (either path), **then** the extra cells are dropped; a row with fewer cells is padded with empty strings — the block always squares to the header.
- **Given** prose containing pipes (`either | or`) as part of a longer paragraph, **when** Enter is pressed, **then** no conversion fires and the paragraph is untouched.
- **Given** a fenced code block containing a pipe table, **when** the migration runs, **then** the fence's content is byte-identical after; **and given** the cursor inside a code block in the editor, **when** a row-shaped line is committed with Enter, **then** no conversion fires.
- **Given** a pipe block with no delimiter row, **when** the migration runs, **then** it is not a gfm table and passes through unchanged.
- **Given** a column whose non-empty cells all parse as numbers, **when** converted, **then** the column's type is number.
- **Given** a column where exactly half the non-empty cells parse as number and half as date, **when** converted, **then** the column is text. Neither type clears [cell-types.md](cell-types.md)'s more-than-half bar, and that threshold decides first; the tie-to-number rule breaks a tie only between two types that have both already cleared it, which disjoint grammars make unreachable.
- **Given** a column inferred number that contains one non-parsing cell, **when** converted, **then** the cell's text is preserved verbatim in the row (downstream: red in grid, NULL in SQL — [cell-types.md](cell-types.md)).
- **Given** a header row with an empty cell and two cells named `Amount`, **when** converted, **then** the empty header becomes `column_<n>` and the duplicate names get distinct keys per [table-block.md](table-block.md)'s dedupe.
- **Given** a document already migrated, **when** the migration runs again, **then** nothing changes — no gfm table exists to match.
- **Given** a document with two pipe tables separated by prose, **when** the migration runs, **then** each becomes a `json-table` block in place with a distinct fresh id, prose byte-preserved, alignment rows dropped.
- **Given** an empty editor line, **when** the user types `| Name | Age |` and presses Enter, **then** a grid appears with columns Name and Age (both text), one empty row, focus in the first cell.
- **Given** an HTML table on the clipboard (spreadsheet copy), **when** pasted, **then** the funnel converts it the same as a markdown paste.
- **Given** a cell containing an escaped pipe (`\|`) or inline markdown (`**bold**`), **when** converted, **then** the stored string holds the literal `|` and the literal `**bold**` characters.

### Isolation

- **Migration** — scenario fixtures under `app/domain/data-blocks/migrations/scenarios/`: `pipe-tables` (two tables, prose between, mixed types, ragged rows — with `expected.md`), `pipe-tables-in-code-fence` and `pipe-tables-no-delimiter` (no `expected.md`; unchanged). Because ids are freshly generated, the harness masks generated table ids with a stable placeholder token before comparing `expected.md` — the one harness accommodation this migration needs; the existing idempotence pass then holds as-is since the re-run changes nothing at all.
- **Live path** — unit tests on the shared transform as a pure function (table shape in, block fields out: keys, inference, ragged squaring, placeholder headers) and on the Enter-trigger predicate (whole-paragraph row shape, code-block exclusion), without mounting the editor. The funnel itself — table node in a transaction never survives — is covered at the editor-story level alongside [grid.md](grid.md)'s stories.
